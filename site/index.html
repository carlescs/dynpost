The HTTP client whose collections live in git.

Dynpost is a lightweight desktop HTTP client. Every request is a readable YAML file in a folder you choose, and Dynpost commits, pulls and pushes that folder for you. No account, no cloud workspace, no proprietary export format.

Your API collections, treated like code

Share, review and version requests the same way you already work with source code.

Files first

A collection is just a folder. Each request is one YAML file you can open, grep, review and edit with any tool. The app always reflects what is on disk.

Git native

Status, diffs, commit, pull, push and branches from inside the app, using your existing git setup and credentials. Merge conflicts are reported, never auto-resolved.

Local and private

Secrets, cookies, tokens and response history stay in a git-ignored .dynpost/ folder on your machine and never end up in the repository.

Small, predictable diffs

Dynpost writes YAML with a stable key order, leaves out empty sections and only rewrites a file when its content actually changed. Opening and saving never reformats anything, so a pull request shows exactly what changed in a request.

  • File names are slugs of the request name
  • {{variables}} come from the selected environment
  • Folder settings in _folder.yaml apply headers and auth to everything inside
  • Mark requests or environments local-only to keep them out of git
requests/users/create-user.yaml 
name: Create user
method: POST
url: "{{baseUrl}}/users"
headers:
  Content-Type: application/json
auth:
  type: bearer
  token: "{{apiToken}}"
body:
  type: json
  content: |
    {
      "name": "Ada Lovelace"
    }

Everything you need, nothing you don't

A focused tool for building, sending and sharing HTTP requests.

Build and send requests

Method, URL, query parameters, headers and bodies: JSON, text, form-data, URL-encoded, GraphQL and binary files.

Auth helpers

Basic, Bearer token, API key and OAuth 2.0 (client credentials, and authorization code with PKCE in the system browser).

Inspect responses

Status, a timing breakdown with redirects, headers, cookies, and a pretty-printed body with HTML and PDF previews.

Organize collections

Nested folders, drag and drop, Markdown docs per request, and values captured from responses into variables.

Environments and history

{{variable}} substitution per environment, optional cookie jars, and local response history compared in a diff view.

Sync with git

Changed files and diffs, commit, pull, push and branches, with a status that stays current on its own.

Load test

*.run.yaml plans send requests from concurrent virtual users, with live statistics and pass/fail thresholds.

Bring your collections

Import from Postman, Insomnia, HAR and OpenAPI/Swagger; export for Postman and Insomnia.

Work with an AI assistant

An optional built-in MCP server lets Claude and other assistants browse, edit and send your requests. Off by default.

Download for Linux

Dynpost needs git for workspace sync and the system webview: WebView2 on Windows (included in Windows 10 and 11), WebKit on macOS, and GTK 3, WebKitGTK 4.1 and libnotify on Linux. The builds are not code-signed yet, so Windows SmartScreen or macOS Gatekeeper may ask you to confirm the first launch. See the install notes and all releases.

Deliberately small

Dynpost leaves out pre-request and test scripting, functional collection runners, mock servers, cloud accounts and hosted team workspaces. Git is the collaboration layer. Dynpost is in early development: usable day to day, but the file format and features may still change.
